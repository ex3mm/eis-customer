# Проверка статуса аккредитации Заказчика на ЕИС

Отдельный Go-микросервис проверяет точное совпадение ИНН + КПП одновременно в двух реестрах `zakupki.gov.ru`:

- реестр организаций (44-ФЗ);
- реестр заказчиков 223-ФЗ, только статус `0 — Зарегистрирован` (статус «Исключен» в запрос не передается).

Оба HTTP-запроса выполняются параллельно. Значение `found: false` возвращается только после успешного ответа и разбора обоих источников. При сетевой ошибке, таймауте, HTTP 408/429/5xx или пустом ответе выполняется не более одной повторной попытки. HTTP 4xx, блокировка и CAPTCHA не повторяются.

## API

| Метод | URL | Назначение |
|---|---|---|
| `GET` | `/health` | liveness-проверка |
| `GET` | `/docs` | Swagger UI |
| `GET` | `/openapi.yaml` | OpenAPI 3.0 |
| `POST` | `/api/v1/accreditation/check` | проверка ИНН + КПП |

Запрос:

```bash
curl -X POST http://localhost:8080/api/v1/accreditation/check \
  -H 'Content-Type: application/json' \
  -d '{"inn":"6317024749","kpp":"631701001"}'
```

Если включена авторизация (`EIS_AUTH_ENABLED=true`), добавьте заголовок:

```bash
-H 'Authorization: Bearer your-secret-key'
```

Без заголовка или с неверным токеном endpoint возвращает `401 application/problem+json`. `/health`, `/docs` и `/openapi.yaml` намеренно остаются открытыми. На production включите авторизацию и задайте отдельный длинный случайный ключ; не сохраняйте его в `.env.example`.

Успешный ответ:

```json
{
  "inn": "6317024749",
  "kpp": "631701001",
  "found": true,
  "sources": {
    "fz44": {"found": false},
    "fz223": {"found": true}
  },
  "checked_at": "2026-09-08T09:00:00Z"
}
```

`found` равен `true`, если точное совпадение найдено хотя бы в одном реестре. Заголовок `X-Cache` содержит `HIT` или `MISS`. Ошибки возвращаются как `application/problem+json`. Отдельные JSON Schema находятся в каталоге [`schema`](schema/), тот же контракт описан в Swagger.

## Локальный запуск

Нужен Go 1.25+.

```bash
cp .env.example .env
set -a
. ./.env
set +a
go test ./...
go run ./cmd/eis-customer
```

## Настройка

Все настройки задаются ENV. Динамические `searchString`, `inn`, `kpp` всегда берутся из тела API-запроса. URL собираются отдельным компонентом; каждый статический query-параметр можно переопределить собственной ENV-переменной из `.env.example`.

Основные переменные:

| Переменная | По умолчанию | Описание |
|---|---:|---|
| `EIS_SERVER_PORT` | `8080` | порт внутри процесса/контейнера |
| `EIS_DOCS_ENABLED` | `true` | публикация Swagger |
| `EIS_AUTH_ENABLED` | `false` | Bearer-авторизация |
| `EIS_AUTH_API_KEY` | — | обязательна при включенной авторизации |
| `EIS_REQUEST_TIMEOUT` | `20` | таймаут одной попытки, секунды (целое число без суффикса) |
| `EIS_MAX_RETRIES` | `1` | допустимы только `0` или `1` |
| `EIS_RETRY_DELAY` | `500` | пауза перед повтором, миллисекунды (целое число без суффикса) |
| `EIS_PROXIES` | — | список proxy URL через запятую, round-robin по попыткам |
| `EIS_CACHE_ENABLED` | `false` | кешировать полностью успешные ответы |
| `EIS_CACHE_TTL` | `1h` | срок жизни in-memory кеша |
| `EIS_FIXTURES_MODE` | `off` | `off`, `write` или `read` для HTML-фикстур |
| `EIS_FIXTURES_DIR` | `fixtures` | корневой каталог фикстур |
| `EIS_44_BASE_URL` | URL ЕИС | endpoint реестра организаций |
| `EIS_223_BASE_URL` | URL ЕИС | endpoint реестра 223-ФЗ |

Полный перечень параметров обоих URL приведен в [`.env.example`](.env.example). Чтобы исключить параметр из URL, задайте соответствующую ENV пустой строкой. Для 223-ФЗ defaults содержат только `customer223Status_0=on&customer223Status=0`; переменной статуса «Исключен» намеренно нет.

### TLS и сертификаты Минцифры

Предпочтительный вариант — положить PEM/CRT сертификаты Минцифры в `./cert` и указать:

```dotenv
EIS_TLS_CA_CERTS_DIR=/app/cert
EIS_INSECURE_SKIP_TLS_VERIFY=false
```

Каталог рекурсивно читается при запуске, сертификаты добавляются к системному trust store. Если сертификаты еще не установлены, доступен временный небезопасный режим:

```dotenv
EIS_INSECURE_SKIP_TLS_VERIFY=true
```

Он отключает проверку подлинности TLS-сертификата внешнего сайта и должен использоваться только как аварийный fallback.

### Прокси

Поддерживаются `http://`, `https://` и `socks5://`; на каждой попытке выбирается следующий прокси:

```dotenv
EIS_PROXIES=http://proxy:3128,http://user:password@proxy2:8080,socks5://127.0.0.1:1080
```

Учетные данные прокси удаляются из логов. Пустое значение означает прямое соединение.

## Docker Compose

```bash
cp .env.example .env
# отредактировать .env, особенно auth/TLS/proxy
docker compose up -d --build
docker compose ps
curl http://localhost:8080/health
```

Для сервера создайте каталог `cert`, положите туда доверенные сертификаты и оставьте read-only mount из `compose.yaml`. Если сертификаты не используются, закомментируйте `EIS_TLS_CA_CERTS_DIR` либо включите временный insecure-режим.

## Эксплуатационные замечания

- Кеш локальный для процесса и сбрасывается при перезапуске; для нескольких реплик нужен внешний кеш.
- Изменение HTML-разметки ЕИС приводит к `502`, а не к ложному `found: false`.
- Swagger UI загружает статические файлы с CDN; `/openapi.yaml` доступен без CDN.
- Сервис не логирует тело запроса или секреты прокси/API.
